# Feature Spec: モバイル向けタッチ操作（プル更新・スワイプ・オートコンプリート・スケルトン）

## 概要

モバイルファーストの方針に合わせ、一覧画面の操作と読み込み体験を改善する。
いずれもタッチ操作の「近道」であり、同じ操作はボタン等でも行えること（キーボード・
スクリーンリーダー利用者が機能を失わない）を前提とする。

## 機能

### プル更新（`PullToRefresh`）

- ホーム（在庫一覧）と買い物リストで、ページ最上部から下に引っ張ると再取得する
- ホーム: `["items"]` クエリを無効化して再取得。買い物リスト: 表示中タブ／買い物中モードの取得元を `refetch`
- 縦方向のドラッグのみ対象（横方向は無視）。ページがスクロールされている間、選択モード中は無効
- 引っ張り中はブラウザ標準のプル更新（リロード）を抑止する（`touchmove` を non-passive で受ける）
- 判定ロジックは `src/lib/gesture.ts`、状態管理は `usePullToRefresh`

### スケルトンスクリーン

- 既存の `Skeleton` atom を使い、実際のレイアウトと同じ形のプレースホルダを表示する
- `ItemListSkeleton`（カード/リスト表示別）、`ShoppingListSkeleton` として共通化
- `role="status"` + `aria-busy` で読み込み中を支援技術へ伝える

### スワイプアクション（`SwipeableRow`）

- ホームのリスト表示（`ItemListRow`）: 左スワイプ=1個消費、右スワイプ=メモ編集（グリッドのクイックボタンと同じ操作）
- 買い物リスト（`ShoppingRow`、`swipeEnabled`）: 右スワイプ=在庫に追加、左スワイプ=削除（確認ダイアログ経由）
- 72px 以上で確定。縦スクロールとは軸判定で区別し、スワイプ直後の誤タップ（リンク遷移）は抑止する
- 選択モード中・消費不可（在庫0、他アイテム処理中）の行ではその方向を無効にする

### オートコンプリート（`AutocompleteInput`）

- 買い物リストの追加フォームと、アイテム新規登録フォームの名前欄で、登録済みアイテム名を候補表示する
- 前方一致 → 部分一致の順。全角/半角・大文字小文字・ひらがな/カタカナの差を吸収（`src/lib/autocomplete.ts`）
- ARIA combobox パターン（↑↓ で選択、Enter で確定、Esc で閉じる）。自由入力は常に可能
- 候補データは `useNameSuggestions`（ダッシュボードと同じ `useItems` キャッシュを共有、追加通信なし）

## 対象外

- 購入店名の入力は既存の `datalist` のまま
- 楽観的な履歴・購入名からの候補（在庫に無い名前の補完）は将来の拡張
