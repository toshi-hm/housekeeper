# Feature Spec: バーコード即時消費（クイックコンシューム）

> 親 Issue: #924

## 概要

現状バーコードスキャンは「新規登録」の入口としてしか使われていない。日々の
「使った」記録を、台所でパッケージを手に取った瞬間に一番早く行える手段として
再利用できるようにする。

## スコープ

- やること:
  - 既存の `BarcodeScanner`（`@zxing/browser` ラッパー）で読み取ったバーコードが
    既存 `items`（バーコード一致、`deleted_at IS NULL`）と一致した場合、従来の
    「新規登録フォームへ遷移」の代わりに「1点/一部使用」を選べるワンタップ確認
    シート（`QuickConsumeSheet` molecule、新規）を表示する
  - 対象アイテムが複数ロット（同一バーコードで複数 `items` 行）を持つ場合は
    FIFO（`purchased_at` 昇順、既存の消費ロジックの前提と同じ）で先頭ロットを
    消費対象として提示する
  - 消費処理自体は既存の `useConsumeItem` / `consumeLot`（`opened_remaining`
    デクリメント、`units` 繰り下げ、`consumption_logs` 記録）をそのまま呼び出す
  - スキャン結果が既存アイテムと一致しない場合のみ、従来通り新規登録フォームへ
    フォールバックする（挙動変更なし）
- やらないこと:
  - 消費ロジック自体（デクリメントアルゴリズム）の変更はしない（PLANS.md §4.2 を
    そのまま利用）
  - 複数ロットの消費順をユーザーが手動で選び直すUIは v1 では作らない（FIFO 固定）
  - 新規登録フローの UI 変更はしない（不一致時は完全に既存動線のまま）

## ユーザーストーリー

- 台所でパッケージを手に取り、既存アプリのバーコードスキャンを開いて読み取る
- 登録済みの商品なら、その場で「1点使う」ボタンをワンタップして確認シートを閉じる
- 未登録の商品なら、従来通り新規登録フォームが開く

## 画面

- `QuickConsumeSheet` molecule（新規、bottom sheet 相当）:
  - アイテム名・現在の残量表示
  - 「1点使う」ボタン（`opened_remaining` を `content_amount` 分減らす、既存の
    消費デクリメントアルゴリズムに委譲）
  - 「一部使用」で数量入力 → 既存の `ConsumeForm` 相当の入力 UI を再利用
  - 「新規登録として追加する」の脱出リンク（同一商品を複数ロットとして
    別途登録したいケース向け、既存の新規登録フローへ遷移）

## データへの影響

なし。既存スキーマ・既存消費ロジックの再利用のみ。

## エラー

- バーコード一致は取得したがオフラインで消費 API が失敗した場合、既存の
  消費エラーハンドリング（トースト + リトライ可能な状態維持）をそのまま使う
- 複数ロットの先頭ロットが `units = 0`（使い切り状態）の場合は次のロットへフォールバック

## 対象範囲（v1）

- `BarcodeScanner` の呼び出し元（ダッシュボードの「Scan」導線）に
  `onMatch` コールバックを追加し、一致判定とシート表示の分岐を追加する
- 既存の新規登録フロー（不一致時）・消費ロジックは変更しない

## 工数目安

S〜M（既存のバーコード基盤・消費ロジックを再利用できるため、確認シートUIの
追加が主）
