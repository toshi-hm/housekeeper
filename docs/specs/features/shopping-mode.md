# Feature Spec: 買い物中モード（Shopping Mode）

## 概要

買い物リスト・低在庫・期限間近アイテムを1枚の縦スクロールに統合表示し、「店内で
片手・濡れた手・歩きながら」使うことに特化した画面（親 Issue: #926、実装済み・
未ドキュメント化のため本 spec で追認する）。編集操作は持たず、大きめタップ領域の
確認・追加・購入アクションのみに絞る（`docs/specs/accessibility.md`）。

## 既存実装（v1 範囲、実装済み）

- ルート: `_auth.shopping.tsx` 内のモード切替（買い物リスト画面と同一ルートの表示切替）
- `ShoppingModeView` organism（`src/components/organisms/ShoppingModeView.tsx`）
  - `plannedItems`（買い物リストの未購入アイテム）を購入・削除できる
  - `lowStockItems` / `expiringItems`（低在庫・期限間近の在庫アイテム）を
    ワンタップで買い物リストへ追加できる（`addedItemIds` で追加済みは disabled）
  - `isLoading` の間はスケルトン表示（元データ未取得を0件と誤表示しない、#977）
  - 全て空なら「確認事項なし」の空表示
- `ShoppingModeAlertRow` molecule（低在庫/期限間近の1行表示）
- `ShoppingRow` の `resolveCheapestStore` で最安店舗ヒントを行に表示（`useStorePriceComparisons`
  の再利用、#697 / #854 / #979）
- 購入確定は `PurchaseDialog`（数量・単価・期限入力）経由で `purchaseShoppingItem` を呼ぶ
  （`src/hooks/useShoppingList.ts`）。この関数は冒頭で `requireOnline()` を呼び、
  オフライン時は `OfflineError` を投げて即座に失敗する

## ユーザーストーリー（既存）

- 店内で買い物リストを開くと、リスト・低在庫・期限間近が1画面にまとまっている
- 低在庫/期限間近のアイテムをその場で買い物リストに追加できる
- 買ったものをその場で購入確定でき、次に来たときには消えている

## 拡張 1: オフライン耐性強化（アクションのキューイング）（#981）

### 課題

`docs/specs/features/pwa.md` は「編集系はオフライン時にエラー表示で抑止（キューイング
しない）」という方針だが、買い物中モードは「店内・電波の弱い場所での利用」を明示的に
想定した画面であり、まさにこの画面の主要アクション（購入確定・買い物リストへの追加）
がオフライン時に機能しないのは本末転倒。

### スコープ

- やること: 買い物中モードの「購入確定」（`purchaseShoppingItem`）と「アラートから
  買い物リストへ追加」（`useUpsertShoppingItem` 経由）の2アクションに限定し、
  オフライン時はローカルキュー（`localStorage` ベース、新規 `useOfflineActionQueue`
  的な薄いラッパー）に積み、`window.ononline` / 再接続検知で自動的にリプレイする
- やらないこと: 買い物中モード以外の編集操作（アイテム編集・削除等）へのキューイング
  拡大はしない（`pwa.md` の既存方針を維持）。競合解消（キュー内アクションとサーバー
  側の以後の変更が衝突するケース）は #952 で導入済みの楽観的排他制御パターンに
  乗せ、リプレイ時に競合が起きた場合は該当アクションのみ失敗としてトースト通知し、
  ユーザーに手動再試行を促す（自動マージはしない）

### データへの影響

なし（サーバー側スキーマ変更不要）。キューは `localStorage` に
`{ id, kind: "purchase" | "add-alert", payload, queuedAt }[]` の形で保持する。

### 技術ポイント

- `requireOnline()` を呼ぶ2関数の呼び出し元（`ShoppingModeView` の `onPurchase` /
  `onAddAlert` ハンドラ）だけをオフラインキュー対応にラップし、`useShoppingList.ts`
  自体のオンライン専用契約は変えない（他画面からの呼び出しは従来通りブロックする）
- Service Worker の再接続検知は既存の `src/lib/pwa.ts` の仕組みを流用する

### 工数目安

M

## 拡張 2: 見込み合計金額表示（#982）

### 課題

レジに並ぶ前に予算オーバーを事前に把握できない。

### スコープ

- やること: `ShoppingModeView` の「買い物リスト」セクション上部に、`plannedItems`
  のうち `resolveCheapestStore` が値を返すもの（＝比較データがあるもの）を
  最安値ベースで合算した見込み合計金額を表示する。比較データが無いアイテムは
  金額に含めず、「一部のアイテムは概算に含まれていません」という注記を出す
- やらないこと: 実際の会計金額との自動突き合わせ・レシートスキャンとの連携はしない
  （それは別提案 #941 の対象）

### データへの影響

なし。既存 `useStorePriceComparisons` の再利用のみ。

### 技術ポイント

新規バックエンド・外部API連携は不要。`ShoppingModeView` 内のクライアント側合算のみ。

### 工数目安

S

## 拡張 3: 「カートに入れた」の軽量チェックオフ機能（#983）

### 課題

現状、買い物リスト行でできるアクションは「在庫に追加」（`PurchaseDialog` を開く
重い購入確定フロー）と「削除」のみ。店内でカートに入れた瞬間に、レシート内容が
確定する前の「取った」という軽い意思表示をしたいニーズがある。

### スコープ

- やること: 買い物中モードの各行に、購入確定とは別の軽量チェックボックスを追加し、
  ON にすると取り消し線表示にする。状態は端末内 `localStorage`（サーバー同期不要）
  に `{ [shoppingListItemId]: true }` の形で保持し、購入確定（`onPurchase`）または
  行削除時にそのアイテムのチェック状態をクリアする。永続化はセッションを跨いでも
  残ってよいが、UIに「会計後にリセットする」ヒントテキストを添える
- やらないこと: サーバー側へのチェック状態同期、複数デバイス間の共有はしない

### データへの影響

なし。

### 技術ポイント

`localStorage` オンリー。既存の `resolveCheapestStore` 等と同様、`ShoppingModeView`
props 経由でチェック状態と toggle ハンドラを受け取る設計にし、`_auth.shopping.tsx`
側で `localStorage` 読み書きを担う（他の永続クライアント状態と同じレイヤー分け、
PLANS.md §6.1）。

### 工数目安

S
