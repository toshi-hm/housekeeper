# Feature Spec: 棚卸し写真チェック（シェルフスキャン）

> 親 Issue: #927

## 概要

レシート一括登録は「購入時」の入力を助けるが、時間が経つと実在庫とシステム上の
在庫がズレていく（食べたのに記録し忘れた、記録したのに使い切っていない等）。
棚や冷蔵庫の写真を1枚撮ると、既存のレシート一括登録と同じ Gemini Vision 基盤で
写っている商品を認識し、システム上の在庫と突き合わせて差分を提示、ワンタップで
一括補正できるようにする。

## スコープ

- やること:
  - 新規 Edge Function `shelf-scan`（`receipt-scan` と同様の Gemini Vision 呼び出し
    パターン、RLS スコープ・レート制限を踏襲）を追加し、画像から「写っている商品名
    候補」の配列を返す
  - クライアント側で、認識結果を同一カテゴリ/保管場所の既存 `items`（`deleted_at
IS NULL`、`units > 0`）と突き合わせ、以下2種類の候補を提示する:
    - 「システム上にあるが写真に写っていない」（食べきった？候補）
    - 「写真にあるがシステムに未登録」（未登録候補）
  - 候補一覧 UI（`ShelfScanReviewPanel` organism、`ReceiptReviewPanel` と同様の
    レビュー画面パターン）で、ユーザーがワンタップで「使い切り扱いにする」
    （既存の `useSoftDeleteItem` 相当、または `units=0` 化）/「新規登録する」
    （既存の新規登録フォームへの遷移、詳細は手入力）を選べるようにする
- やらないこと:
  - 画像1枚からの自動確定（マッチング候補は必ずユーザーの確認を経る、確定操作を
    自動実行しない）
  - 個数・内包量の写真からの推定はしない（新規登録の候補提示のみ、詳細は
    手入力に委ねる）
  - カテゴリ・保管場所をまたいだ全在庫の突き合わせはしない（対象カテゴリ/保管場所を
    ユーザーが撮影前に選択する前提とする。1枚の写真に写る範囲は棚/冷蔵庫1区画程度
    が現実的なため）

## ユーザーストーリー

- 冷蔵庫の中を撮影する前に、対象の保管場所（例:「冷蔵庫」）を選ぶ
- 撮影すると、システム上の在庫との差分候補が一覧表示される
- 「食べきった」候補にチェックを入れて一括補正、「未登録」候補は個別に新規登録へ進む

## 画面

- 起動導線: ダッシュボードの「Scan」メニューに「棚卸し写真チェック」を追加
- `ShelfScanCapturePage`（保管場所選択 + カメラ起動、`BarcodeScanner` と同様の
  フルスクリーンモーダルパターン）
- `ShelfScanReviewPanel` organism（差分候補一覧 + 一括補正アクション）

## データへの影響

なし。既存 `items` / `categories` / `storage_locations` の読み取りのみ。
新規テーブルは不要。

## エラー

- Gemini Vision の認識精度限界により誤検出があり得るため、候補は「提案」であり
  ユーザーの明示的な確認操作なしに在庫を変更しない
- 画像アップロード失敗・Vision API エラー時は既存の `receipt-scan` と同様、
  トースト表示 + 再試行を促す（新規登録手動フローへのフォールバックは常に可能）

## 対象範囲（v1）

- 新規 Edge Function `shelf-scan`
- `ShelfScanCapturePage` ルート + `ShelfScanReviewPanel` organism
- 差分マッチングロジック（クライアント側、`src/lib/shelfScanMatch.ts` 新設）
- i18n `shelfScan` 名前空間

## 工数目安

L（Vision推論・マッチングロジック・差分UIの新規実装。既存のレシートスキャンの
Edge Function/UIパターンを流用可能）
